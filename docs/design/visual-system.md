# Визуальная система

Источник реализации: app/globals.css. До изменения прочитай только нужные токены
и правила секции вместе с её компонентом.

## Обязательные правила
Сохраняй графитовый фон, светлый текст, красные акценты, технические моноширинные
подписи и крупную display-типографику. Используй существующие роли и компоненты.
Не добавляй разовые text-[...], font-size или rem-размеры текста, если пользователь
не просит расширить систему. Наличие старых исключений не разрешает новые.

Общая сетка: .site-shell, --hero-rail-x, --hero-grid-gap, --hero-grid-col,
--hero-grid-row и 12 колонок на desktop. Новая отдельная сетка требует запроса.
Контент секции по умолчанию имеет inset со всех сторон через --section-inner-inset;
edge-to-edge допустим по явному запросу. Текущую композицию Work сохраняй при
несвязанных изменениях.

Перед изменением глобальной переменной найди все использования через rg.
Сохраняй font faces, Tailwind theme, палитру, hero-размеры и overflow,
если задача не касается этих правил.

## Текущие токены
| Роль | Значение / источник |
| --- | --- |
| Фон / графит | #050505 / #111111 |
| Текст / вторичный | #e6e2da / #8a8a8a |
| Красный / яркий | #8b0000 / #d10a0a |
| Заголовки | PaluiSP Bold |
| Текст секций | Manrope, font-subheading |
| Технический текст | системный monospace |
| Заголовок Hero | --hero-title-size |
| Lead Hero | --hero-lead-size |
| Внутренний отступ | --section-inner-inset → --hero-copy-offset |

body использует Arial; Manrope подключается явно. Цвета повторены в @theme и :root.
About, Work и Contact используют Hero-токены. Contact повторяет типографические
роли Hero, высоту CTA и оформление System Online; футер использует text-xs.
Process и кейсы пока имеют
локальные размеры — это долг, а не завершённая унификация.

Исторические Work overrides нельзя удалять без проверки итогового каскада.
При консолидации сначала фиксировать текущий вид и состояния, затем менять структуру.
Карточки Work и изображения доски кейса не имеют видимой обводки в покое;
hover и focus-visible дают полный контур --accent-red-bright. В Work и кейсе контур
рисуется inset-псевдоэлементом поверх изображения, не меняя его пропорции.
У Work art нет физического border, который мог показывать светлый фон.
Общий .board-dismiss для закрытия Work, возврата к работам и закрытия изображения
использует общие размеры с .work-board-filter: min-height 38px, padding 0 15px,
текст 0.66rem, line-height 1.5, letter-spacing 0.1em; gap действия 8px.
На экранах до 767px обе группы имеют min-height 32px и padding-inline 9px.
Ширина определяется текстом, без растягивания Close
до ширины длинной подписи возврата; top/right остаются согласованными.
Правый край действий сдвинут внутрь на половину --hero-grid-gap;
кадр просмотра центрируется по X, его верх на desktop совпадает с верхом Close.
Ширина симметрично учитывает натуральную ширину кнопки и --hero-grid-gap,
поэтому действие не перекрывает изображение; на compact кадр начинается ниже Close.
Проверка 2026-10-07 на 2560×1440: фильтры, Close Work, возврат и Close изображения
имеют высоту 38px; в просмотре страницы Abby между кнопкой и кадром остаётся 24px,
перекрытия нет. Сборка и сценарий закрытие Work → кейс → изображение → закрытие
→ возврат к работам успешны.
Размеры проверки — [responsive](responsive.md); эффекты — [motion](motion.md).
