# Простая админка

Открыть http://127.0.0.1:3000/admin. При первом локальном входе задать пароль от 10 символов, повторить его и сохранить. Для следующих входов используется этот пароль. Сессия действует восемь часов. Выйти можно кнопкой справа сверху.

Новый кейс: название, тип, вкладка, год, сфера, краткое описание, обложка и изображения. Доступны вкладки «Сайты», «Презентации», «Печать», «Социальные сети» и «Рекламные баннеры». Первая обложка полного кейса автоматически добавляется внутрь, если галерея пуста. Изображения показаны компактными миниатюрами по порядку: стрелки переставляют их, «Заменить» загружает другой файл на то же место, крестик убирает изображение из кейса. Полей подписи и описания у изображений нет; внутри кейса они показываются без визуальных подписей. PNG/JPG/WebP до 50 МБ и 120 мегапикселей, до 40 изображений в кейсе. Все новые загрузки сохраняются в WebP с качеством 92. Изображения со стороной больше 16 383 px пропорционально уменьшаются до этого предела WebP без обрезки; меньшие не увеличиваются. Размеры записываются после конвертации. Например, 3400×27000 превращается в 2063×16383. Исходный файл отдельно не сохраняется; прежние медиа не переконвертируются. «Длинная страница» включает просмотр с прокруткой. Шесть текстовых разделов кейса необязательны. Пустые разделы не отображаются.

«Черновик» сохраняет кейс только в админке. Выбрать «Опубликован» и нажать «Сохранить и опубликовать», чтобы работа появилась в выбранной вкладке. Флажок «Избранное» добавляет её также в общий список избранных. Номер новой работы назначается после текущих 14 кейсов; номера удалённых работ не используются повторно. В «Ваших кейсах» находятся все добавленные через админку работы, включая черновики. «Текущие кейсы сайта» содержит все опубликованные работы: исходные и добавленные владельцем. Нажатие на любую открывает редактор. Исходные кейсы сохраняют прежние адреса и номера; изменения хранятся отдельно от кода. Все черновики доступны также в списке «Скрытые кейсы». Изменения появляются после обновления страницы сайта.

У выбранного сохранённого кейса рядом со статусом есть «Скрыть с сайта» и «Удалить кейс». Скрытие сразу переводит сохранённую версию в черновик: работа исчезает из публичного списка и её страница становится недоступна. Несохранённые правки остаются в форме. «Вернуть на сайт» публикует сохранённую версию снова; для публикации правок сначала использовать обычное сохранение. Удаление требует подтверждения с названием кейса, убирает работу из сайта и всех списков админки и открывает пустой редактор. Вернуть удалённый кейс через админку нельзя. Действия работают для собственных и исходных кейсов. Удалённые исходные кейсы не появляются снова после перезапуска: в хранилище остаётся внутренняя отметка удаления. Файлы изображений при удалении кейса остаются на диске.

В карточке над формой указаны название выбранной работы, номер, источник и фактический сохранённый статус: «Опубликован на сайте», «Черновик» или «Ещё не сохранён». Изменённый статус до сохранения показан отдельно как предстоящее действие. Несохранённые изменения отмечаются; переключение на другую работу требует подтверждения их потери.

Флажок «Одиночная работа — без страницы кейса» оставляет обложку и краткое описание в блоке работ, убирает «Смотреть кейс» и отключает отдельную страницу. Галерея внутренних изображений и подробное описание становятся недоступны в форме. Уже добавленные изображения и текст сохраняются, чтобы восстановиться при снятии флажка. Обложка одиночной работы автоматически внутрь не добавляется. Старые сохранённые записи без этого флага продолжают работать как полные кейсы.

Хранилище: .portfolio-content/cases.json, admin.json, media/*.webp и метаданные изображений. Каталог исключён из Git и находится вне public. Пароль хранится как scrypt-хеш; admin.json содержит также ключ подписи сессии. Не отправлять этот файл и не включать его в публичные архивы. Резервировать весь каталог .portfolio-content. PORTFOLIO_CONTENT_DIR позволяет указать другой постоянный абсолютный каталог. Загрузка ещё не прикреплённых файлов сохраняется до ручного обслуживания; автоматического удаления медиа нет. Изображения доступны по случайным публичным URL, поэтому в черновики следует загружать только материалы, допустимые к публикации.

Первая версия рассчитана на один Node.js-сервер с постоянным диском. Она пока работает на этом компьютере. Для будущего облачного хостинга с временной файловой системой необходимо заменить хранение на базу и объектное хранилище; простой перенос сборки туда не сохранит контент. Первичная настройка пароля через браузер разрешена только для локального development-сервера без прокси. На production до запуска задать пароль локальным скриптом scripts/setup-admin.cjs в приватном терминале, затем использовать HTTPS. Никакого стандартного пароля нет.


Проверка: npm.cmd run build, затем npm.cmd run check:admin. Проверки создают изолированное хранилище во временном каталоге и используют порт 3302; основной пароль и данные не меняются. ADMIN_TEST_PORT задаёт другой свободный порт. Флаг --keep-server для scripts/check-admin.cjs оставляет сервер для визуального теста.
