> Исторический обзор до организации harness. Не является действующей инструкцией.
> Актуальная карта — [ARCHITECTURE.md](../../ARCHITECTURE.md), задачи — [backlog](../plans/backlog.md).

Дата обзора: 27 сентября 2026 года.

Документ описывает фактическое состояние рабочей копии, включая незакоммиченные изменения. Предложения ниже не являются уже выполненным рефакторингом. Правила работы с репозиторием находятся в `AGENTS.md`.

## 1. Идея и назначение сайта

Это персональное портфолио дизайнера с подачей в виде цифрового терминала: тёмный фон, красные сигнальные акценты, технические подписи, рамки фокуса, крупные заголовки, видео и интерактивные эффекты.

По текстам Hero и About основное обещание — выразительный визуальный образ бизнеса: сайты, презентации и digital-упаковка. Сайт сам демонстрирует авторский подход к композиции и взаимодействию.

Предполагаемый путь посетителя:

1. Понять специализацию и характер дизайнера на первом экране.
2. Получить контекст об авторе и его опыте.
3. Открыть работу на интерактивной доске и перейти к подробному кейсу.
4. Уточнить услуги и порядок сотрудничества.
5. Связаться с дизайнером.

Сильная сторона — узнаваемая визуальная система. Основной текущий разрыв — между проработанностью эффектов и готовностью содержимого: работы, страницы кейсов и контакты ещё содержат заглушки.

## 2. Технологическая основа

Версии указаны по `package.json`, а не как результат проверки установленного дерева зависимостей.

| Область | Реализация |
| --- | --- |
| Приложение и маршруты | Next.js 16.2.4, App Router |
| Интерфейс | React / React DOM 19.2.5 |
| Типизация | TypeScript 6.0.3, `strict: true` |
| Стили | Tailwind CSS 4.2.4, глобальный CSS, отдельные CSS Modules |
| Анимации | `framer-motion` с диапазоном `^12.38.0`, CSS, Canvas 2D и `requestAnimationFrame` |
| Данные | Локальные TypeScript-массивы |
| Ассеты | Локальная папка `public/` |
| Команды | npm: `dev`, `build`, `start` |

В просмотренной структуре нет собственного API, базы данных, авторизации или CMS. Для текущего масштаба портфолио они не требуются. Состояние взаимодействий хранится локально в компонентах; глобальный state manager также не нужен.

  SelectedCases.tsx          Оболочка раздела работ
  WorkBoard.tsx              Перетаскивание доски, карточки, предпросмотр

  ScrambleTitle.module.css   Локальные стили заголовка

### Маршруты и композиция

- `/` — Preloader, Header, технический контроллер SmoothSectionScroll, затем Hero → About → SelectedCases → Services → Process → Contact внутри `main.page-snap`.
- `/work/[slug]` — поиск кейса по slug; `generateStaticParams()` получает значения из `data/cases.ts`; неизвестный slug вызывает `notFound()`.
- RootLayout применяется к обоим маршрутам. Header и Preloader принадлежат главной, на страницах кейсов они не подключены. На кейсе есть ссылка возврата на главную.

### Серверные и клиентские границы

`layout.tsx`, главная страница, маршрут кейса и статические секции остаются серверными компонентами. Клиентские границы выделены для Preloader, About, WorkBoard, SmoothSectionScroll, CustomCursor, LiquidReveal, ScrambleTitle и GridOverlay.

Это разумное исходное разделение. Переводить всю страницу в `use client` ради одного эффекта не стоит. Возможное дальнейшее выделение статической части About имеет смысл только при конкретной задаче или измеренной пользе.

### Поток данных кейса

```text
data/cases.ts ──────────────> /work/[slug] и generateStaticParams()
      │
      └──> WorkBoard.workItems → карточка → предпросмотр → ссылка на кейс
              ↑
       локальные переопределения названия, типа и описания
```

Сейчас доска дополняет `cases[0]`–`cases[3]` и заменяет часть полей. Поэтому «Nexora» ведёт на `/work/project-01`, где заголовок остаётся «Project 01». Индексная связь также делает перестановку массива данных рискованной.

## 4. Дизайн-система

### Источник правил

Активный источник — `app/globals.css`. Tailwind используется для утилит, а значительная часть композиции задана именованными классами `.hero-*`, `.about-*`, `.work-*`, `.build-*`.

| Роль | Текущее решение |
| --- | --- |
| Фон | `#050505`, графит `#111111` |
| Основной текст | `#e6e2da` |
| Вторичный текст | `#8a8a8a` |
| Акценты | `#8b0000`, яркий красный `#d10a0a` |
| Display-шрифт | PaluiSP Bold |
| Основной текст секций | Manrope через `font-subheading` |
| Технические подписи | Моноширинный системный стек |
| Базовый шрифт body | Arial; Manrope применяется явно |
| Сетка | 12 колонок, `--hero-rail-x`, `--hero-grid-gap`, `--hero-grid-col` |
| Вертикальный модуль | `--hero-grid-row` |
| Внутренний отступ | `--section-inner-inset`, связанный с `--hero-copy-offset` |
| Оболочка | `.site-shell`, общие направляющие и углы секций |

Размеры основных элементов Hero выражены через `clamp()`. About и актуальная Work используют связи с Hero-токенами, в том числе для заголовков. Это сохраняет общий масштаб.

Цвета продублированы в `@theme` и `:root`. Сейчас значения согласованы, но при дальнейшем развитии лучше выбрать первичный набор и ссылаться на него, чтобы исключить расхождение.

### Где система пока неполная

- Нет полностью унифицированного набора семантических ролей для заголовка секции, заголовка карточки, lead, body и meta во всех разделах.
- Process, Contact и страница кейса используют собственные `text-[...]` и локальные размеры. Header и отдельные детали Hero тоже содержат такие значения.
- Общие декоративные рамки и боковые подписи повторяются в JSX; Services использует свой вариант разметки.
- CSS содержит 5687 строк на дату обзора. В нём последовательно накоплены старые варианты Work и новые переопределения: `WORK grid refit`, `WORK reference layout lock`, `Interactive Work board`, `Final Work HUD overrides` и последующие поправки.

Проблема CSS — прежде всего зависимость результата от истории каскада. Нельзя просто удалить ранние блоки: актуальные правила могут наследовать от них свойства.

### Адаптивная стратегия

Главный ориентир — 2560×1440. Full HD должен сохранять ту же композицию при меньшем масштабе. Детальная мобильная адаптация отложена, но доступность текста и действий обязательна уже сейчас.

При будущем упорядочивании CSS следует сохранить существующую сетку и имена токенов. Общие семантические имена можно вводить через совместимые алиасы после проверки всех потребителей, а не массовым переименованием.

## 5. Взаимодействия и важные зависимости

| Система | Поведение и связь с остальным сайтом |
| --- | --- |
| Preloader | Scramble текста, процент по времени, запуск предзагрузки видео. Выход начинается по таймеру около 2050 мс; есть страховочный таймер. Это не индикатор фактического объёма загрузки. |
| Hero | Зацикленное muted-видео с постером; CTA ведёт к `#contact`. Видео и его предзагрузка используют один путь, записанный в двух компонентах. |
| Scroll | CSS задаёт обязательный snap для html/body; JS перехватывает wheel, touch и клавиши и анимирует переход между секциями за 680 мс. |
| WorkBoard | Pointer capture, порог начала drag, ограничение смещения через ResizeObserver; предпросмотр с общей layout-анимацией обложки и ссылкой на маршрут кейса. |
| About | Анимации опыта и шкал навыков; LiquidReveal переключает фоновые изображения через Canvas. |
| CustomCursor | Курсор со шлейфом; учитывает fine pointer/hover и reduced motion. Режим закрытия предпросмотра связан также с CSS Work. |
| GridOverlay | По умолчанию скрыт, клавиша T переключает вспомогательную сетку; ввод текста и модификаторы учитываются. |
| CRT | CSS рамки сохранён, но `ENABLE_TV_EFFECT = false` в layout: глобальная телевизионная рамка сейчас выключена. Локальные текстуры секций при этом остаются. |

У просмотренных обработчиков есть cleanup слушателей, observer и основных циклов анимации. Это хорошая база, но не замена профилированию.

Reduced motion поддержан в нескольких системах, однако не единообразно: Scroll проверяет настройку при монтировании; у Hero-видео и Preloader не найден отдельный режим её обработки. Это задача на согласованность поведения, а не повод удалять эффекты.

## 6. Что стоит изменить

### Приоритет 1 — путь от работы до обращения

**Единая модель кейса.** Перенести название, описание, тип, обложку и содержимое подробной страницы в `data/cases.ts`. Существующие slug сохранить. Доска должна получать готовые записи без переопределения бизнес-содержимого и без связи через индекс массива.

Практический состав модели: slug, title, type, year, industry, summary, cover, blocks. Для cover — путь, alt и соотношение сторон; для blocks — задача, ограничения, роль автора, решение, изображения и результат. Размещение на доске допустимо хранить отдельно по slug: это свойство представления.

**Реальные контакты.** В `Contact.tsx` сейчас `t.me/placeholder`, `vk.com/placeholder`, `hello@example.com`. До публикации заменить подтверждёнными адресами. Выдумывать их нельзя.

**Содержательные кейсы.** Сейчас подробные страницы используют общий массив англоязычных заглушек, а доска — `MEDIA PLACEHOLDER`. Начать с одного полностью оформленного кейса, затем применить проверенную структуру к остальным. Численные результаты включать только при наличии подтверждения; для концептов честно обозначать статус.

### Приоритет 2 — предсказуемость управления

**Уточнить правила Scroll.** Глобальный `handleKeyDown` не исключает кнопки, ссылки, поля ввода или открытый dialog и вызывает `preventDefault()` для Space и стрелок. Это создаёт конфликт с клавиатурной активацией кнопок и взаимодействиями внутри предпросмотра. Wheel также переключает секции без проверки, остался ли непрочитанный контент внутри высокой секции.

Сохранить ощущение переходов, но предусмотреть исключения для интерактивных элементов, открытого предпросмотра, вложенной прокрутки и секций выше viewport. Учесть `defaultPrevented` и смену reduced motion. Проверить это отдельными сценариями, а не менять длительность анимации наугад.

**Завершить доступность предпросмотра.** WorkBoard уже имеет кнопки, Escape, `role="dialog"` и `aria-modal`. Однако в коде нет переноса фокуса внутрь, удержания фокуса и возврата к открывшей карточке. Кнопка закрытия расположена вне элемента с ролью dialog. Нужен единый доступный контейнер с корректным управлением фокусом и фоном.

**Не связывать доступ к работам только с JS-предпросмотром.** Сейчас карточки — кнопки, а ссылка появляется после открытия. Предусмотреть обычный доступ к странице кейса: например, отдельную ссылку или простой список работ как запасной вариант.

### Приоритет 3 — управляемость визуальной системы

**Собрать актуальные стили Work.** Сначала зафиксировать состояния в QHD: доска, drag, открытие, просмотр, закрытие. Затем свести правила одного селектора в понятные блоки, сохранив итоговые значения и адаптивные исключения. Лишь после этого удалять доказанно неиспользуемые классы и распределять файлы.

**Довести типографические роли до всех страниц.** Process, Contact и кейсы подключить к общим ролям и внутренним отступам. Это расширение дизайн-системы, которое следует выполнять отдельной согласованной задачей, а не незаметной правкой размеров.

**Выделить небольшой общий декор секции.** Компонент рамки/боковых меток оправдан повторениями в Hero, About и Work. Он должен отвечать за декор и принимать подписи, не навязывая секциям одинаковую композицию.

**Уточнить служебные файлы.** `AGENTS.md` ссылается на `.agent/PLANS.md`, которого сейчас нет; правила лежат в корневом `PLANS.md`. Ссылку стоит исправить отдельно. `AboutBackup.tsx` не найден среди импортов — кандидат на архивирование после подтверждения, что вариант больше не нужен. В рамках обзора ничего не удалено.

### Приоритет 4 — готовность к публикации

- Добавить индивидуальные metadata кейсов, изображение для шаринга и описание с реальной специализацией; сейчас metadata в layout общие и краткие.
- После определения публичного домена настроить canonical, sitemap и robots. Не подставлять предполагаемый домен.
- Добавить отдельные команды проверки типов и линтера, затем небольшой набор проверок маршрутов и взаимодействий. Начать с известных рисков: одинаковые данные кейса, неизвестный slug, Space на кнопке, Escape/Tab в предпросмотре, достижимость конца высокой секции.
- Измерить загрузку и плавность эффектов до оптимизации. Hero MP4 занимает около 1,73 МБ; сам по себе этот размер не доказывает проблему. Нужны данные о загрузке, декодировании, Canvas и частоте кадров.
- Согласовать reduced motion для всех движущихся частей, сохраняя статические постеры и читаемый контент.

## 7. Рекомендуемая структура при следующем этапе

Текущая плоская папка `components/` ещё допустима. Следующая схема полезна при реальной работе над перечисленными областями; переносить всё сразу ради дерева папок не требуется.

```text
app/                         Маршруты и общая оболочка
components/
  sections/                  Hero, About, SelectedCases, Services, Process, Contact
  work/                      WorkBoard, CasePreview, CaseCover
  effects/                   Preloader, CustomCursor, LiquidReveal, ScrambleTitle
  layout/                    Header, SectionFrame, GridOverlay, SmoothSectionScroll
data/
  cases.ts                   Единое содержание кейсов и его типы
  site.ts                    Подтверждённые контакты и общие сведения
styles/                      При необходимости — после консолидации каскада
  tokens.css                 Цвета, шрифтовые роли, сетка и отступы
  base.css                   Reset, базовые элементы и глобальное поведение
  sections/                  Стили крупных секций
public/                      Опубликованные ассеты
```

`app/globals.css` при таком переходе остаётся точкой входа глобальных стилей. CSS Modules уже применяются локально; их можно использовать для изолированных механизмов. Не стоит одновременно переносить файлы, переименовывать токены и менять внешний вид: такие изменения трудно проверить.

Контент услуг и процесса можно пока оставить рядом с компонентами. Выносить каждый короткий массив в отдельный файл необязательно. Общие данные кейсов и контактов имеют более очевидную ценность как единый источник.

## 8. Что сохранить и что пока не нужно

Сохранить узнаваемую терминальную подачу, авторскую типографику, красные акценты, общую сетку, порядок секций и интерактивную доску. Существующее разделение маршрутов и клиентских эффектов подходит задаче.

По содержанию я бы усилил доказательства компетенций. Шкалы вроде «Figma 10/10» менее убедительны, чем роль в реальном проекте, принятые решения и результат. Их можно оставить частью терминальной эстетики, но не делать главным аргументом. Восемь услуг стоит сверить с фактическим фокусом: основные направления выделить, дополнительные сгруппировать. Это редакторская рекомендация, а не установленный дефект.

Сейчас не нужны CMS, база данных, авторизация, глобальное хранилище состояния, универсальный конструктор секций или большая UI-библиотека. Также не стоит добавлять новые эффекты до завершения кейсов и основного сценария связи.

Не следует удалять CRT, курсор, прелоадер или медиаресурсы просто из-за их сложности. Это защищённые части замысла; изменения требуют отдельной задачи и проверки поведения.

## 9. Порядок дальнейшей работы и проверка

1. Объединить данные доски и страниц, оформить один настоящий кейс, указать контакты. Результат: посетитель узнаёт один и тот же проект на всех этапах и может написать автору.
2. Исправить конфликты прокрутки и фокус предпросмотра. Результат: работы и контакт доступны мышью и клавиатурой, длинный текст достижим.
3. Упорядочить Work CSS с фиксацией исходного вида в 2560×1440. Результат: внешний вид сохранён, новые правки не требуют очередного финального override.
4. Завершить общие типографические роли, страницы кейсов и метаданные. Результат: главная и внутренние страницы воспринимаются как один продукт.
