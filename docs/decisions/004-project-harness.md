# 004 — Harness проекта

Дата: 2026-09-27. Статус: принято в задаче организации документации.

Контекст: большой AGENTS.md смешивал карту, дизайн, запуск и ограничения;
ARCHITECTURE.md совмещал устройство сайта и рекомендации.

Решение: короткая точка входа, тематические правила, фактическая архитектура,
отдельные ADR и планы. Корневой PLANS.md остаётся источником правил ExecPlan.
active/completed — индексы; каждый существенный план — отдельный файл.
Исходный обзор сохранён как исторический материал.

Альтернатива — один большой документ — усложняет выбор минимального контекста.
Последствие разделения: нужно проверять ссылки и не дублировать правила.
Модельные профили — инструкции, не исполняемый маршрутизатор.
Пересмотр структуры нужен, только если навигация мешает реальной работе.
