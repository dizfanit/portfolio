# DIZFANIT DESIGN
Портфолио web/UI/UX-дизайнера. Приоритеты: визуал, UX, типографика, осмысленная анимация, адаптивность, производительность.

## Работа
- Сначала эти инструкции и git status. Читай минимум нужного через rg и целевые диапазоны; перед чтением более 5–7 файлов объясни причину. Не сканируй сборки, зависимости, бинарные ассеты.
- Отвечай кратко; подробности — по необходимости или запросу.
- Сохраняй чужие изменения. Назови область влияния; правь только запрошенное, минимально.
- Без явного запроса сохраняй прелоадер, курсор, CRT, Hero, порядок секций и slug кейсов.
- Используй существующие токены, 12 колонок и внутренний inset. Произвольные размеры текста — только по запросу расширения дизайн-системы. До изменения глобальной переменной найди все использования.
- Проверяй затронутое поведение и зависимости. После TypeScript/компонентов/маршрутов обязателен `npm.cmd run build`. Визуальная проверка: 2560×1440, остальные размеры — по responsive.
- Удаляй только временные файлы своей задачи; не чисти ассеты, логи, состояние проекта.
- Обновляй документацию при изменении знаний; предложения не выдавай за факты.
- Сложные функции/значительные рефакторинги: ExecPlan по [PLANS.md](PLANS.md), регистрация в active, ведение до завершения. Мелким правкам план не нужен. Backlog не разрешает новые задачи.
- Предпочтителен GPT-6 Sol; Luna — механика, GPT-6.1 Sol с уровнем размышлений xhigh — глубокий анализ, сложные решения и ревью вместо Astra. Файлы модель не переключают.
- Дополнительные агенты — только с разрешения пользователя/задания. Исключение: один локальный read-only Qwen по qwen для узкого сбора контекста, сокращающего чтение основной моделью; без дальнейшего делегирования.
- При заполнении контекста субагента примерно на 50–60% дождаться завершения его ограниченного этапа, получить краткую передачу и создать свежего агента для продолжения. Без точной телеметрии заранее ограничивать объём этапов; не выдавать оценку процента за измерение.
